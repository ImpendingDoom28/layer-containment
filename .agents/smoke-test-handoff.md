## Known baseline (updated 2026-11-17)

- In this headless Chromium environment the WebGL game scene does not render, and the **main-menu tests fail too** — the page stalls at the final "Preparing graphics..." loading stage (`ShaderReadyGate` never resolves), so every test that waits for the menu (`smoke`, `controlsIntro`, `i18n`, `mobile`, `shaders`, `testingLevel`, `controlSchemes`) **fails on a clean `master` as well**. Re-verified against `master` on 2026-11-17 (retries=1: 8 failed, 1 flaky, 27 passed — the same failure class). The 2025-10-09 note that main-menu tests pass is stale.
- Full-suite runs under 50% workers are flaky on top of that (GPU stalls from concurrent Chromium instances): the exact failure set churns between runs. To assess a branch, run the suite with `--retries=1` and re-run any branch-specific failures **in isolation** (`npx playwright test <file> -g "<name>"`); failures that pass in isolation are contention flakes, not regressions. Only flag a regression if a test fails in isolation on the branch but passes in isolation on `master`.
- The base-health ECS refactor (`feature/ecs-health-component`) left this baseline unchanged: same 8 pre-existing failures on `master` and on the branch.
- The ECS request refactor (no action→action calls) kept the baseline unchanged too: enemy death is a `requestEnemyDeath` trait consumed by `EnemyDeathSystem` (one-frame delay at 0 HP before the kill is settled — targeting/AoE/medic skip 0-HP enemies); the system settles the kill by calling the domain's own `removeEnemy` action (actions never call actions, and no action internals are exported). End-of-path base damage is a generic `damageRequest` trait (in `src/core/ecs/traits/damage.ts`) on the base consumed by `ApplyDamageSystem` (generic damage authority, works on any entity with `HealthInfo`); `ApplyBaseDefeatSystem` raises `requestBaseDefeat` when the base is dead and `GameProcessSystem` (`runBaseDefeatSystem`) consumes it. Unit tests: 96 passing, `tsc` shows only the 6 pre-existing errors, build OK.
